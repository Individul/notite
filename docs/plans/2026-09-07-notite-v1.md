# Plan: Notițe v1 — notite.dumitru.cloud

## Context

Dumitru are un cloud personal (dumitru.cloud) cu două aplicații live: Sarcini și Știri. Vrea o a treia, **Notițe**, care să ajute în rutina zilnică: captură rapidă de gânduri, fără foldere, fără formulare. Deciziile luate în discuție:

- **Primul ecran = notița de azi.** O notiță per zi (fus Europe/Chisinau), creată la cerere, cursorul la sfârșit. Notițele durabile, cu titlu, stau într-o listă laterală.
- **Doar Dumitru acum**, dar fiecare notiță are coloană `owner` (email) din prima zi, ca al doilea utilizator să funcționeze doar prin filtrare. Nimeni nu vede notițele altcuiva.
- **Autentificare prin Cloudflare Access** (cod pe e-mail), fără cod de login propriu. JWT-ul verificat pe server; fără Access configurat → 503 (eșuează închis).
- **Text în clar în D1** (bază proprie `notite`), deci căutare full-text pe server.
- **Online-only cu plasă de siguranță**: salvare automată; dacă salvarea eșuează, textul rămâne în localStorage și se retrimite când revine netul. PWA instalabilă, fără service worker.
- **În afara v1**: etichete `#`, legături `[[ ]]`, partajare, imagini, AI, offline complet.
- **Repo nou** `Individul/notite`, clonat la `C:\Users\prisa\notite`.

Stiva oglindește `C:\Users\prisa\stiri\site`: Astro 7 `output: 'server'` + `@astrojs/cloudflare` 14, Worker cu assets, `import { env } from "cloudflare:workers"`, D1 cu SQL brut în `lib/db.ts`, CSS simplu cu tokens în `Base.astro`, totul în română (UI cu diacritice, comentarii și commit-uri fără).

Diferențe deliberate față de stiri/site: Notițe are JavaScript pe client (autosave) și rute API JSON; testele D1 folosesc `@cloudflare/vitest-pool-workers` 0.22, care cere **vitest ^4.1** (nu 5). Versiuni verificate pe npm: astro 7.3.1, @astrojs/cloudflare 14.3.0, wrangler ^4.129.

## Schema D1 (`migrations/0001_init.sql`)

```sql
CREATE TABLE notite (
  rid           INTEGER PRIMARY KEY,          -- rowid stabil pentru FTS5, niciodata expus
  id            TEXT NOT NULL UNIQUE,         -- uuid public din URL
  owner         TEXT NOT NULL,                -- email Access, minuscule
  tip           TEXT NOT NULL CHECK (tip IN ('zi', 'nota')),
  data_zi       TEXT CHECK (data_zi IS NULL OR data_zi GLOB '[0-9][0-9][0-9][0-9]-[0-9][0-9]-[0-9][0-9]'),
  titlu         TEXT,
  corp          TEXT NOT NULL DEFAULT '',
  creat_la      TEXT NOT NULL,                -- ISO 8601 UTC cu ms, generat de aplicatie
  actualizat_la TEXT NOT NULL,                -- idem; concurenta optimista
  CHECK ((tip = 'zi' AND data_zi IS NOT NULL) OR (tip = 'nota' AND data_zi IS NULL))
);
CREATE UNIQUE INDEX idx_notite_owner_zi ON notite(owner, data_zi);   -- o notita de zi per owner si data
CREATE INDEX idx_notite_owner_tip_act ON notite(owner, tip, actualizat_la DESC);

CREATE VIRTUAL TABLE notite_fts USING fts5(
  titlu, corp, content = 'notite', content_rowid = 'rid',
  tokenize = 'unicode61 remove_diacritics 2'                          -- "eticheta" gaseste "etichetă"
);
-- triggere notite_ai / notite_ad / notite_au (AFTER INSERT / DELETE / UPDATE OF titlu, corp)
-- cu tiparul standard FTS5 external-content ('delete' + insert)
```

Etichetele din v2 devin tabel `etichete(rid_nota REFERENCES notite(rid), eticheta)` fără schimbări aici.

Funcțiile din `db.ts` primesc toate `(db, owner, ...)` și fiecare WHERE include `owner = ?`:

| Funcție | Esență |
|---|---|
| `notaZi(db, owner, data)` | `INSERT ... ON CONFLICT(owner, data_zi) DO NOTHING`, apoi SELECT → idempotent |
| `citesteNota(db, owner, id)` | `WHERE id=? AND owner=?` → `Nota \| null` |
| `actualizeazaNota(db, owner, id, {titlu, corp, baza})` | `UPDATE ... WHERE id=? AND owner=? AND actualizat_la=?`; `changes=0` → recitește → `lipsa` sau `conflict` cu rândul curent |
| `stergeNota` | DELETE, returnează `changes > 0` |
| `listeazaNote` | tip `nota`, `substr(corp,1,120) AS rezumat`, ORDER BY actualizat_la DESC LIMIT 200 |
| `zileRecente(n=14)` | tip `zi` AND corp <> '' ORDER BY data_zi DESC |
| `cauta(db, owner, interogare)` | `notite_fts MATCH ? AND n.owner = ?`, `snippet(...)` cu markere `\u0001`/`\u0002`, `ORDER BY bm25(notite_fts, 3.0, 1.0)` LIMIT 50 |

Interfața exportată `Nota { id, tip, data_zi, titlu, corp, creat_la, actualizat_la }` (fără owner, fără rid).

## Autentificare și API

**`lib/identitate.ts`** (pură, verificator injectabil, implicit `verificaAccessJwt` din access.ts):
1. Dacă `teamDomain && aud`: fără header `Cf-Access-Jwt-Assertion` → 403; verificare eșuată → 403 cu motiv; ok → email `trim().toLowerCase()`. Access are prioritate și local.
2. Altfel, dacă `devEmail && cfg.dev` → ok cu `devEmail`.
3. Altfel → 503 „Cloudflare Access nu este configurat.”

`cfg.dev` se calculează doar în `middleware.ts`: `import.meta.env.DEV || hostname ∈ {localhost, 127.0.0.1}`. Trei lacăte împotriva scurgerii în producție: `import.meta.env.DEV` e `false` static la build, `DEV_EMAIL` trăiește doar în `.dev.vars` (gitignored, niciodată în `vars`/secrets), iar cererile de producție vin pe domeniul custom. Teste: `DEV_EMAIL` setat + hostname producție + dev=false → 503; Access configurat + `DEV_EMAIL` + fără JWT → 403.

**Middleware** pe fiecare cerere: eșec → `/api/*` primește JSON `{ eroare }`, paginile text simplu cu status; succes → `locals.email`. Paginile nu citesc niciodată `env.ACCESS_*` direct.

**Rute JSON** (toate `Cache-Control: no-store`; erori `{ eroare }`):

| Rută | Corp | Succes | Erori |
|---|---|---|---|
| `POST /api/notite` | `{ titlu? }` (mereu tip `nota`) | `201 { nota }` | 400 titlu > 200, 415 fără application/json |
| `GET /api/notite/:id` | — | `200 { nota }` | 404 |
| `PUT /api/notite/:id` | `{ titlu?, corp, baza }` | `200 { nota }` | 400 (JSON invalid, corp > 100 000, titlu pe `zi`), 404, **409 `{ eroare: "conflict", nota }`** când `actualizat_la ≠ baza` |
| `DELETE /api/notite/:id` | — | 204 | 404 |
| `POST /n/noua` (form) | — | 303 → `/n/:id` | 403 dacă `Sec-Fetch-Site` nu e same-origin/none |

CSRF: POST/PUT cer `Content-Type: application/json` (altfel 415), fără antete CORS. Concurență: compare-and-set în UPDATE, deci două salvări simultane nu pot câștiga amândouă.

## Pagini și navigare

- `/` → `PaginaZi` pentru `aziChisinau()` (via `Intl.DateTimeFormat('en-CA', { timeZone: FUS })`), fără redirect, ca `start_url` din PWA să deschidă mereu azi.
- `/zi/[data]` → aceeași componentă; `ziValida` (regex + round-trip prin `Date.UTC`) altfel 404. Zilele viitoare sunt permise (planificare).
- Navigare în `Bara`: `← /zi/{ieri}` · `Azi` (→ `/`) · `/zi/{mâine} →`, prin `ziVecina(data, ±1)` pe UTC. Antet: `etichetaZi` („Azi”, „Ieri”, „Mâine” sau ziua săptămânii) + `fmtZi` („luni, 7 septembrie 2026”).
- `/n/[id]` → titlu `<input>` deasupra textarea (salvate împreună), buton „Șterge” (confirm → DELETE → `/`). 404 când `citesteNota` e null (acoperă alți owneri).
- `/cautare?q=` → server-rendered; rezultatele leagă spre `/n/:id` sau `/zi/:data`, cu `<mark>` din `fragmentHtml`; stare goală „Niciun rezultat pentru „…””. Caseta de căutare e pe fiecare pagină. `<meta name="robots" content="noindex">` peste tot.
- `ListaNote`: coloană de 300 px la ≥ 900 px; sub, un `<details>` sub antet (fără JS). Secțiuni: „+ Notiță nouă”, „Notițe” (titlu sau „(fără titlu)” + rezumat), „Zile” (ultimele 14 zile nevide).

## Editorul pe client (`src/scripts/editor.ts`)

Bundlat de Astro din `<script>` în `Editor.astro`; importă `lib/markdown.ts` ca previzualizarea să folosească același renderer ca serverul. Citește `data-id`, `data-actualizat`, `data-tip`.

Stări: `curat` („salvat”), `murdar` („modificat…”), `se-salveaza` („se salvează…”), `offline` („nesalvat, offline”), `eroare` („nesalvat, reîncerc…”), `conflict` („notița s-a schimbat în altă parte — reîncarcă”).

| Din | Eveniment | Spre / acțiune |
|---|---|---|
| curat / murdar | `input` | murdar; scrie ciorna `{titlu, corp, baza, la}` în `localStorage["notite:ciorna:"+id]`; repornește timer 800 ms |
| murdar | timer, `blur`, `visibilitychange`→hidden, `pagehide`, Ctrl/Cmd+S | se-salveaza; PUT (cu `keepalive` la hidden/pagehide și corp < 60 KB); `input` în timpul salvării → `dinNou = true` |
| se-salveaza | 200 | `baza = nota.actualizat_la`; șterge ciorna; `dinNou ? murdar : curat` |
| se-salveaza | 409 | conflict; păstrează ciorna; oprește autosave; banner cu „Reîncarcă” |
| se-salveaza | eroare rețea / 5xx | `navigator.onLine === false ? offline : eroare`; retry la `online` și cu backoff 5 s, 10 s, 20 s, 60 s |
| offline / eroare | retry | se-salveaza |
| oricare | Ctrl/Cmd+S | `preventDefault()`, salvează imediat |

La încărcare: dacă există ciornă pentru id: `ciorna.baza === data-actualizat` → aplică silențios, murdar, salvează imediat (cazul offline → reload); altfel banner „Ai o ciornă nesalvată de la {la}” cu „Folosește ciorna” / „Renunță”. Fără `beforeunload`.

Cursor la sfârșit pe pagina de azi (`focus()` + `setSelectionRange(len, len)`). Mobil: viewport cu `interactive-widget=resizes-content`, textarea `font-size: 17px` (fără zoom iOS), `field-sizing: content` + fallback JS `height = scrollHeight`, `autocapitalize="sentences"`. Comutator „Scrie / Citește” schimbă `hidden` între textarea și `#previzualizare`.

## Markdown

Renderer scris de mână (~120 linii), fără bibliotecă: `marked` nu sanitizează și escape-înainte strică fence-urile. Bloc: fence-uri ``` (conținut escapat, fără inline), `#`/`##`/`###`, liste `- `/`* `/`1. `, paragrafe separate prin linie goală (newline simplu → `<br>`). Fiecare bucată de text trece prin `escapeHtml` **înainte** de regulile inline (`**b**`, `*i*`/`_i_`, `` `cod` ``, `[text](url)`, autolink `https://`). URL-ul trebuie să înceapă cu `https?://`, `mailto:` sau `/` (verificat pe brut), altfel text simplu; linkurile ies cu `target="_blank" rel="noopener noreferrer"`. Teste: `<script>` escapat, `javascript:`/`data:` respinse, `&` în URL, fence păstrează `*`/`#`, bold în listă, titluri.
